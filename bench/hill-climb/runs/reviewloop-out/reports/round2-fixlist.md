# Round 2 fix list (from round2-reviewer.md)

1. limiter.py: clock readings of +/-inf accepted and poison `last` / the log forever -> treat any non-finite clock reading as an internal error (deny, fail closed, state untouched). Backward clock step locking a key out until the clock catches up -> no longer possible once denial stops writing state (see 3): a backward reading grants nothing (elapsed clamped to 0) and leaves the stored baseline alone.
2. config.py / limiter.py: `float(10**400)` raises OverflowError, escaping as a non-ConfigError -> catch OverflowError in every coercion path and raise ConfigError. Tests added for load_config and both constructors.
3. limiter.py: incremental float refill drifts (rate=0.2 polled every 0.1s is denied at t=5.0) -> stop rewriting (tokens, last) on denial; compute available tokens in one step from the last admitted state, write state only on admission. Rounding then happens once per admission, not once per poll. Test added for rate=0.2 at the exact boundary.
4. Validation inconsistency and duplication -> single set of coercion helpers in config.py (`coerce_float`, `coerce_int`, with an `allow_str` switch) used by load_config and both constructors; numeric strings accepted in load_config only (frozen `test_values` requires it); integer strings for burst now parsed through float so "1000.0" and "1e3" are accepted and "2.5" rejected, consistent with how floats are treated; `_INT_PATTERN_OK` removed; `numbers.Real` / `numbers.Integral` used so numpy scalars are accepted. Constructor validation is kept, not removed: round 1 asked for it, the README's "invalid configuration is rejected with ConfigError" covers the limiter's own settings, and without it a `None` rate makes every allow() deny silently. Signatures are unchanged. Decision recorded in REPORT.md as the spec point the two rounds disagreed on.
5. tests/test_limiter.py: reset-race test asserted nothing -> assert every result is a bool, stats totals match the call count, and the state is consistent afterwards (reset then exactly one admission).
Not fixed: per-key memory growth (pre-existing, outside the four requirements); README not updated to describe string coercion (reviewer note, not a defect; behaviour is unchanged from v1).
